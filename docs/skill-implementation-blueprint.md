# CTCSOL 说课试讲陪练 Skill v0.1：实施蓝图

## 1. 文档职责

本文档回答“Skill 如何实现”。产品需求、目标用户、范围、非目标和发布计划以 [MVP PRD](ctcsol-skill-mvp.md) 为准。

v0.1 是一个可安装、可对话调用的 Skill 文件夹，不是独立网站。本阶段不需要另写平台级技术说明。

## 2. v0.1 可观察目标

给定一段清晰的考试材料文字，Skill 能够：

1. 忠实复原材料，不编造看不清的内容。
2. 根据材料估计学习者级别或级别范围，并展示证据与不确定性，不默认固定为 HSK2。
3. 提取 2-3 个有题面依据的候选教学点。
4. 对候选点进行定性比较，并等待用户确认。
5. 为已确认的微用法生成 3 分钟说课、7 分钟试讲和动态板书。
6. 按质量门槛检查并修正后，交付可开口练习的 Markdown 结果。

周三晚首个里程碑只要求“清晰文字输入”跑通。截图核对和练习复盘在周四补齐。

## 3. 文件架构

```text
ctcsol-interview-coach/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
│   ├── exam-rules-2026.md
│   ├── material-and-point-selection.md
│   ├── grammar-accuracy-and-sources.md
│   ├── teachable-grammar-index.md
│   ├── speaking-3min.md
│   ├── microteaching-7min.md
│   ├── interaction-feedback-boardwork.md
│   └── quality-rubric.md
└── assets/
    ├── teaching-plan-card.md
    ├── microteaching-storyboard.md
    └── rehearsal-review-card.md
```

### `SKILL.md`

只保留：

- 何时触发、服务边界和两种模式。
- 共享状态流程和必须停顿的用户确认点。
- 必须遵守的失败条件和 reference 路由。
- 最终输出应使用的 asset。

不在 `SKILL.md` 里复制八份 reference 的详细内容。

### `references/`

用于改变模型决策的详细规则，按需读取：

| 文件 | 什么时候读 | 只负责什么 |
|---|---|---|
| `exam-rules-2026.md` | 生成说课、试讲或判断时长时 | 官方已核实的流程、时长、环节与未确定项 |
| `material-and-point-selection.md` | 读取材料、生成候选点时 | 材料核对、选点、微用法缩小与定性比较 |
| `grammar-accuracy-and-sources.md` | 用户选定教学点后 | 知识源优先级、语法核验流程和已核验语法卡 |
| `teachable-grammar-index.md` | 生成候选点或记录测试结果时 | 已测试语法点的证据、定性结论、风险、置信度和状态 |
| `speaking-3min.md` | 选点确认后生成说课时 | 3 分钟说课结构、时间和口语化要求 |
| `microteaching-7min.md` | 选点确认后生成试讲时 | 7 分钟教学链路、语法与例句一致性 |
| `interaction-feedback-boardwork.md` | 生成试讲分镜时 | 无真实学生的互动、反馈、纠错、动作和板书 |
| `quality-rubric.md` | 每次完整稿生成后 | 内部质量检查、失败条件和修订顺序 |

### `assets/`

三份 asset 是最终输出模板，不是规则库：

- `teaching-plan-card.md`：说课决策、3 分钟说课稿和关键词速记。
- `microteaching-storyboard.md`：7 分钟分镜、教师台词、学生反应、反馈纠错和板书过程。
- `rehearsal-review-card.md`：实际用时、卡顿、遗漏、问题诊断、精简第二稿和下一轮任务。

## 4. 对话状态流程

```text
接收截图/文字
  -> 复原并核对材料
  -> 估计学习者级别；无法唯一判定时给出选项
  -> 提取 2-3 个候选点
  -> 定性比较并推荐一个
  -> 等待用户确认选点
  -> 核验语法与例句
  -> 生成说课 + 试讲 + 板书 + 速记
  -> 内部质量检查并修订
  -> 用户计时练习
  -> 复盘并生成第二稿
```

不得跳过的两个门：

1. 截图不清时，必须先请用户核对文字。
2. 正式生成说课试讲前，必须获得用户对教学点的确认。

## 5. 最小数据契约

### 材料状态

```yaml
material_text: 核对后的文字
unclear_fragments: []
source_type: image | text
learner_level_estimate:
  options: []
  evidence: 词汇、句式、任务复杂度和来源依据
  confidence: low | medium | high
learner_profile_assumption:
  age: 题面未给时不固定；如生成必须使用则显式说明
  confirmed_level: 用户确认或根据选定教学点后采用的假设
```

### 候选教学点

```yaml
name: 语法、词汇或交际功能名称
evidence: 题面中的具体词句
estimated_hsk: 级别和来源；无法核实则标记不确定
micro_use: 七分钟内只讲的小用法
qualitative_fit: 优先推荐 | 可选 | 不建议
reason: 为什么容易或不容易展开
risk: 过简、过宽、过难、例句风险或缺少互动
confidence: low | medium | high
```

### 已确认教学方案

```yaml
selected_point: 用户确认的点
teaching_objective: 可观察、可在七分钟检测
key_difficulty: 重点与难点不泛化
form_meaning_condition: 已核验的最小说明
core_examples: 2-4 个自然且递进的例句
common_error: 至少一个可纠正问题；如确实不适用则说明
interaction_goal: 学生在试讲中要开口完成什么
boardwork_path: 板书如何随课堂逐步形成
```

## 6. 输出契约

快速出稿结果固定分为五块：

1. **材料与选点决策**：题面、假定、候选点和最终选点。
2. **3 分钟说课**：完整参考稿 + 关键词提纲。
3. **7 分钟试讲**：按时间分镜的可演台词、学生反应与教师处理。
4. **板书过程**：何时写、写什么、最终板书形态。
5. **练习建议**：易卡点、可删减内容和下一步计时任务。

复盘结果固定包含：问题诊断、最高优先级修改、精简第二稿和下一轮只练的 3 个问题。

## 7. 硬性不变条件

- 不编造材料、官方规则、HSK 级别或语法书结论。
- 不把参加 CTCSOL 的中国教师考生与试讲中的外国中文学习者混为同一用户角色。
- 不预设外国中文学习者固定为 HSK2；必须先看材料和题面。
- “HSK2-3 较好讲”只是待验证经验，不是固定选点规则。
- 不使用未校准的“适讲度”数字分数。
- 说课和试讲必须使用同一个微用法、学习者假定和教学目标。
- 例句必须自然，时间相加必须成立，学生必须有实际开口机会。
- 无真实学生时，互动必须包含提问、停顿、复述预设回答和针对性反馈。
- 未检测时不宣布“学生已掌握”。
- 不承诺考试通过。

## 8. 周三晚开发顺序

1. 用官方初始化工具创建 Skill 目录和 `agents/openai.yaml`。
2. 先写 `SKILL.md` 的模式、状态流程、停顿点和 reference 路由。
3. 先填充快速出稿所需的参考：选点、语法核验、说课、试讲、互动板书和质量检查。
4. 完成说课卡和试讲分镜卡；复盘卡先建最小可用模板。
5. 从原创 PDF 第 7-10 页“有点儿/一点儿”案例中分离最小原始材料，运行一次端到端测试；测试时不向生成流程提供 PDF 中的完整旧稿。
6. 将实际失败写入测试记录，只修改有证据的规则。
7. 运行 Skill 结构验证，确认没有占位内容和断链。

## 9. 测试策略

### 首个端到端案例

使用原创 PDF 中“有点儿/一点儿”相关例句和场景，重建一道文字清晰、可以产生多个候选点的最小材料。PDF 完整旧稿是测试后对比基线，不是输入，也不是权威标准答案。记录：

- Skill 是否能引用题面证据，而不是只给语法名称。
- 候选点是否真正不同，而不是同一点的换说法。
- 用户确认前是否停止。
- 说课和试讲是否一致。
- 7 分钟分镜是否可执行。
- 互动、纠错和板书是否具体。
- 新结果是否检出旧稿的时间矛盾、不自然或语义不匹配例句，而不是照抄。

### 失败案例

- 模糊或裁切不完的截图：应停止并请用户核对。
- 无明显语法点的材料：应允许选择词汇或交际功能，不得硬造语法。
- 范围过大的点：应缩小或标记不建议。
- 语法来源不足：应降低置信度，不得伪装已核验。

## 10. v0.1 验收条件

只有同时满足以下条件，v0.1 才算能进入首批内测：

- Skill 目录通过结构验证。
- 至少 5 种不同语言点已跑通，且包含一道无明显语法点的材料。
- 每道案例都有选点证据、完整输出、质量检查和修订记录。
- 没有材料编造、明显语法错误、不自然核心例句、时间不成立、无学生开口或说课试讲不一致。
- 至少有一份可供小红书展示的“原材料 -> 候选点 -> 完整练习方案”案例。

## 11. 延后的技术决策

以下问题在 Skill 输出质量验证前不做技术选型：

- 独立网页、后端、数据库和部署。
- 登录、访问码、支付、次数限制和防复制。
- 第三方 OCR、语音转写或语音打分服务。
- 是否把原始 Skill 文件交付给付费用户。

## 12. 开发中的决策记录规则

- 改变用户、范围、核心流程或发布目标：先更新 MVP PRD。
- 改变文件责任、数据契约、reference 路由或验收方式：更新本蓝图。
- 仅修正某个语法点、例句、模板字段或互动话术：直接更新对应 reference 或 asset，不重写整份 PRD。
